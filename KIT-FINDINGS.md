# Kit findings

Problems found in the zero-debt kit while building this starter (kit commit cfb4405). Each has a reproduction. The kit was not changed.

## Config and tools

1. **`roave/security-advisories` blocks the local PHP.** `dev-latest` conflicts with `php < 8.5.13`; the machine has 8.5.12. Repro: `composer require --dev roave/security-advisories:dev-latest` on PHP 8.5.12. Installs here use `--ignore-platform-req=php`.
2. **Rector 2.9 no longer has `earlyReturn` as a working set.** `->withPreparedSets(earlyReturn: true)` prints "argument is deprecated and no longer applied", yet the kit's `REFACTOR_SETS` regex counts it among the 19 switches, so `refactor-sets` holds an inert flag. Repro: `vendor/bin/rector process --dry-run` with the kit's `rector.php`. The DIJ `strictBooleans` argument does not exist in 2.9 (`Unknown named parameter $strictBooleans`).
3. **rector-laravel's 13 sets rewrite `protected $fillable` and `$hidden` into `#[Fillable]` and `#[Hidden]` attributes.** The catalog row "Model" says `$fillable`. With no skip allowed the attribute form wins. Side effect: the attribute arguments are never executed, so Pest's mutation run reports 8 "uncovered" mutants (`RemoveArrayItem` in the attribute lines), which caps the score at 94.59 with 100% line coverage. Repro: `vendor/bin/pest --mutate --everything` after `rector process`.
4. **A Rector rule that miscompiles with no way to skip it.** `ContainerArrayAccessToMethodCallRector` turns `$app['env'] = 'production';` into `$app->bind('env', 'production');`, which throws `BindingResolutionException`. The kit forbids skips, so the idiom had to be replaced by hand (`detectEnvironment()`), as the kit says. Worth listing next to the three idioms of `templates/tool-configs.md`.
5. **bleedingEdge turns on `internalTag`, which makes every Pest test fail the analyser.** 138 errors of kind `method.internalClass` ("Call to method toBe() of internal class Pest\Mixins\Expectation"). `reference-project/phpstan.neon` has no bleedingEdge include at all, while the catalog and contract point 15 require it: reference and catalog disagree. Here `phpstan-tests.neon` sets `featureToggles: internalTag: false`; stubs do not work (stub validation cannot see vendor classes in `@mixin`). Repro: include `conf/bleedingEdge.neon`, analyse any Pest test with `expect()`.
6. **The reference's Pest support classes do not carry over.** `PestClosureThis` names `Tests\FeatureTestCase`; `arch()` and `pest()->...->beforeEach()` need their own extensions in Pest 5 (`PestArchFunction`, `PestUsesCallClosureThis` here). The catalog's "Top level in tests" lists the first two kinds only.
7. **The dead-code detector has no Laravel knowledge and the reference provider is too small.** Constructors of container-built classes are reported as `shipmonk.deadMethod`, and so are policy abilities, `__invoke` of controllers, `handle()` of middleware, `rules()`, `casts()`, `definition()`, seeders. `reference-project/tests/Support/PHPStan/LaravelMagicUsage.php` covers jobs and notifications only. Repro: `phpstan-tests.neon` without the provider.
8. **The `Config::get()` ban misses the facade form.** The catalog and the reference list only `Illuminate\Config\Repository::get()` and the contract, as instance calls; `Config::get('x')` passes. It needs the same name in `disallowedStaticCalls` (spaze reports it as `Illuminate\Config\Repository::get() (as Illuminate\Support\Facades\Config::get())`). Repro: call `Config::get('x')` in a test file and analyse.
9. **`bootstrap` as a tool path breaks on a normal install.** `bootstrap/cache/packages.php` and `services.php` are generated and untracked; Rector rewrites them (`rector --dry-run` exits 2) and PHPStan reports `classConstant.internalClass` on them. The kit says "every folder that holds PHP" for both. Here both name `bootstrap/app.php` and `bootstrap/providers.php`. Repro: `composer install` then `vendor/bin/rector process --dry-run` with `bootstrap` in the paths.
10. **The optimized autoloader hides new analyser extensions.** The skeleton sets `optimize-autoloader`; a new class named in a `services:` block of a neon file fails with "Class ... not found" until `composer dump-autoload -o`. Repro: add an extension class and run PHPStan.
11. **The hosted DIJ pint config lacks 19 of the 21 strictness rules** (`final_class`, `strict_comparison`, `mb_str_functions`, ... all but `declare_strict_types` and `visibility_required`). The starter uses the kit's `pint.json`, which is DIJ's plus those rules.

## Scripts and rows

12. **The dashboard row `autoload-conformance` writes into `vendor`.** Its command `composer dump-autoload -o` rewrites the autoload files, also in `--offline` (the row is `always`). Run from a copy whose `vendor` is a symlink it re-pointed the real `vendor` classmap at the copy: coverage read 0%. Repro: `ln -s <repo>/vendor copy/vendor; (cd copy && bash scripts/debt-dashboard.sh --offline)`, then run the tests in `<repo>` with coverage.
13. **`checks.sh` cannot run in a repository without a remote.** `git fetch origin main` fails with "cannot fetch origin/main, so the script guard cannot run". A first local commit series has no base. Repro: `bash scripts/checks.sh` in a fresh `git init`.
14. **Configuring the copied scripts needs `[ratchet: script]` tags.** The kit copies the scripts in one commit and the config blocks are filled in later; the guard then fails every changed script ("changed outside its table, FAILS without [ratchet: script]"). The README says a PR that installs the tools needs no tag, which holds only when copy and configuration are one PR. Repro: commit the unconfigured scripts, then fill `kit-config.sh` and run `bash scripts/checks.sh` with the first commit as `origin/main`.
15. **`--self-test` has no fixture for two rows the kit itself names.** `queue-bus-fake-all` and `unused-ignore` print "no fixture for". Cases were added to `selftest_cases` in this repository. Repro: `bash scripts/ci-ratchets.sh --self-test` after adding both rows.
16. **`unused-ignore` cannot be a `json` row for composer-unused.** The tool's config is PHP (`composer-unused.php`), so the row definition "json ... count? <key>" does not apply; the starter counts `NamedFilter::fromString` with a `grep` row on `composer-unused.php?` and the tool needs no ignore today.
17. **`mutation.sh` flakes with Pest's default process count.** `pest --mutate --everything --parallel` on a 12-core machine gave 75% (29 untested, 10 timeouts) against 94.59% with `--processes=4`, same code. Repro: `bash scripts/mutation.sh` with the kit's line. The starter's `mutation.sh` passes `--processes=4`.
18. **`model-strictness-violations` and `cap-ci-duration-minutes` have no subject in a new project.** The first is a counted list of existing violations: a greenfield project has none, and "lists stay deleted" forbids an empty file, so the row is not added. The second needs a host: `bash scripts/debt-dashboard.sh --final` without `--offline` prints `UNKNOWN (could not be measured)` for it until the repository is hosted on GitHub with `gh` set up (the row uses the GitHub command of "Adding a row").
19. **`dependencies-abandoned` is 1 on the kit's own tool set.** `symplify/rule-doc-generator-contracts` is abandoned and required by `driftingly/rector-laravel`, which the kit prescribes. `--final` (online) fails on it and the kit offers no override for an abandoned dev dependency. Repro: `composer audit --locked --abandoned=report`.
20. **Dashboard defaults do not follow `SOURCE_PATHS`.** The README says `SOURCE_FILES` covers the same folders as `SOURCE_PATHS`, but its default holds `app|bootstrap|config` only; and a PHP project with translations has `lang/*.php` outside every default path (`--uncovered` lists them). Both are set by hand here.

## Catalog and guides

21. **`__()` has no typed accessor.** The config facade has `Config::string()`, but `__()` returns `string|array|null`, and every use as a string at level 10 needs a narrowing. The catalog says "`__()` only" and has no row for it. The starter wraps it in `App\Support\Translate::string()`; a translation-key test reads literal keys from that call.
22. **A public page has no home in the "Authorization" row.** "Every route has `can` ..." cannot be met by a page for guests: nobody holds a permission. The localized example page carries only `throttle:read`. The contract test over the routes (`RoutePermissionCoverageTest`) needs a category for public routes.
23. **`composer test:unit` and `--parallel`.** Works with `--parallel --coverage-clover` on Pest 5 (12 processes, 100% on 148 statements); the catalog does not say that, and the first attempt read 0% only because of finding 12.
24. **pcov on macOS.** `pecl install pcov` fails with `pcre2.h not found`; `CPPFLAGS=-I$(brew --prefix pcre2)/include pecl install pcov` works and enables the extension in the global `php.ini`.

## Phase 2 (runtime guards)

25. **The kit's own Rector sets turn a guard's `unlink()` into a facade call that the unit tier cannot run.** `UnlinkFuncCallToFileFacadeDeleteRector` (in the Laravel code-quality set, no skip allowed) rewrites `unlink($path)` to `File::delete($path)`. A guard class and `TemporarySource` run in `tests/Unit`, which never boots the application, so every example fails with "A facade root has not been set". Repro: copy `reference-project/tests/Support/Architecture/EmptyCatchGuard.php`, run `vendor/bin/rector process` on it, then its thin test. The fix used here is `new Filesystem()->delete($path)` (a plain class, which Rector leaves alone); the reference's `TemporarySource` is the one place that deletes a temporary file and the guards should call it, as `EmptyCatchGuard` does here.
26. **The reference guards hold project facts in their bodies.** `MigrationShapeGuard::FIRST_FILE = '2025_01_01'` skips the framework's own migrations dated `0001_01_01_...` in a new project (nothing is under the rule from the first file on); `QueueNameGuard` prints `App\Modules\Observability\Enums\Queue` and "Horizon worker" in its message; `MigrationClassGuard` matches the class names `Permission` and `Role` by their short names, which no project spells that way. Here the first file, the queue enum name and the live permission enums are constructor arguments. The two Pest tests `ArchMigrationsConfigTest` (migration classes and config access) also holds two guards in one file, so two owners edit one file: split by guard.
27. **`@var` on a promoted constructor property.** `ExitGuard`, `MigrationShapeGuard` and others of the reference carry `/** @var list<string> */` on a promoted parameter, which the kit's own rule "no inline `@var`" (row "Narrowing") forbids; `@param` on the constructor is the accepted spelling.

## Phase 2 (http guards)

28. **The route-file spelling of the HTTP table contradicts the formatter-adjacent Rector import rule.** `ImportSpellingGuard` demands `use App\Http\Controllers\Api\Note;` and `Note\IndexController::class` in a route file; `->withImportNames(removeUnusedImports: true)` rewrites that back to one import per controller as soon as the route files are in Rector's paths (they are not in the starter's `rector.php`, so the whole-tree dry run stays clean). Repro: `vendor/bin/rector process routes --dry-run` on a route file written the kit's way. The kit says the analyser paths are "every folder that holds PHP" and does not say the same for Rector: keep `routes` out of `rector.php`, or the two rules fight.
29. **`RateLimiterGuard`'s real-tree case in the reference reads `app` only, so `throttle:60,1` in a route file passes.** The detector fails a `throttle:<digit>` string, but the folder it scans holds no route. Repro: change one `throttle:read` in `routes/api.php` to `throttle:60,1` with the reference's `new RateLimiterGuard(..., 'app', ...)` real case: green. The starter passes a list of folders (`app`, `bootstrap`, `routes`) and the case goes red.
30. **The Rector and Pint pass over a copied guard test rewrites a fully qualified class name inside an example string into `X::class` joined to the string, which changes its meaning.** An example source `\Illuminate\Cache\RateLimiting\Limit::perDay(10);` inside a `namespace App\Providers;` example became `Limit::class . '::perDay(10);'`, whose value has no leading backslash, so the example resolved to `App\Providers\Illuminate\...` and the failing example stopped failing. Two reference datasets (the rate limiter's fully qualified limit, the JSON endpoint's collection class) went blind this way. The examples now spell the backslash in front of the constant. Repro: copy the reference's `RateLimiterArchitectureTest.php`, run `vendor/bin/rector process` and `vendor/bin/pint` on it, and run it (which of the two tools does the rewrite was not isolated).
31. **`DatabaseRuleGuard`, `JsonEndpointGuard` and `ImportSpellingGuard` of the reference are bound to the project's shape.** The first imports `App\Modules\Tenants\Support\TenantScope` and fails a rule on a tenant model unless `tenant_id` is in its chain (a single-tenant app has neither class: the guard does not load), the second takes a list of classes that answer JSON by hand for other systems (an exception list, which `04-guards.md` C1 forbids) and the page response of Inertia, the third an Inertia import half. All three were cut down to the single-tenant, no-Inertia form.
32. **`BareDataReturnGuard` and "a write wraps its Data with its status" fail a controller that the catalog's own note allows.** "A bare DTO returned from a POST answers 201 with the DTO library" (framework traps) is true, and phase 1's `StoreController` relied on it; the HTTP table row says a write wraps it. The guard follows the row, so the starter's store and update controllers return `new JsonResponse($data, Response::HTTP_CREATED)` and `Response::HTTP_OK`. The two sentences of the catalog should name one rule.

## Phase 2 (test guards)

33. **`BannedTestCallGuard` of the reference allows `test(...)`, while the catalog row "Declaring a test" bans it.** The reference guard only fails `test('it ...')`; its own allowed example is `test('a user can sign in', ...)`. With the kit's one spelling (`it(...)` only) the guard bans the function itself. Repro: run the reference guard over a file with `test('works', fn () => ...)`: no finding.
34. **The catalog's `BannedTestCallGuard` list has no entry for `sleep()`, `usleep()`, `allowStray...`, `preventStray...(false)` and `->ignoring()`, which the rows "Hermetic base set-up" and "Architecture presets" say are on its list.** Added here with a failing and a passing example each.
35. **A guard that names a booting base class as `X::class` becomes a booting support type of its own check.** `TestTierGuard` lists `RefreshDatabase::class` and the base test case; its own file is then a "support type that reaches a booting base", so a unit test that imports the guard fails the guard it tests. The kit's Rector (`StringClassNameToClassConstantRector` and `UseClassKeywordForClassNameResolutionRector`, no skip allowed) turns every plain string class name back into `X::class`, so the list can only be kept by concatenation (`'Illuminate\\Foundation\\Testing\\' . 'RefreshDatabase'`). The same rule rewrites an example string that holds `Tests\TestCase::class` into a concatenation with the class constant, which makes the thin test name the booting class: the examples take the name from a variable built from two parts. Repro: put `Tests\TestCase::class` in a string of a unit test and run `rector process --dry-run`.
36. **Three reference guards pass over a missing folder.** `TestClassGuard` skips a suite folder that does not exist, `TestHelperMirrorGuard` reads a missing support folder as empty and `TestTierGuard::pureLayerViolations()` globs layers that match nothing without a word, so a renamed folder turns the real-tree case into an empty pass, which the reference README says its detectors never do. Here each throws when its folder (or, for a list of globs of which some may be absent, every glob) is missing.
37. **`TestLocationGuard` has no home for a test of `database/seeders` or `lang/`.** The reference homes (`Database`, `Lang`, ...) exist, but the catalog's tier rule says nothing about where a seeder test lives; the starter's phase 1 tests sat at `tests/Feature/Seeders` and `tests/Feature/Translations` and failed the guard. They moved to `tests/Feature/Database/Seeders` and `tests/Feature/Lang`.

## Phase 2 (structure guards)

38. **The catalog row "Listener" cannot be met for commands.** It says the bootstrap file names the `Listeners` and `Commands` folders of the modules. `withEvents(discover: [__DIR__ . '/../app/Modules/*/Listeners'])` takes a glob (`EventServiceProvider::discoverEvents` globs and drops what is no directory, so it is safe with no listener yet), but `withCommands([...])` does not: `Kernel::load()` filters its paths with `is_dir()`, so `app/Modules/*/Commands` is silently skipped and a command in a module is never registered. Repro: add `->withCommands([__DIR__ . '/../app/Modules/*/Commands'])`, put a command class in `app/Modules/Notes/Commands`, run `php artisan list`: absent. The module's folder must be named per module, or the command listed by class. The starter has no module command yet and holds only the events half in `BootstrapRegistrationGuard`.
39. **A Pest `arch()` rule over a namespace with no class throws instead of passing.** `arch(...)->expect('App\Modules\*\Exceptions')->classes()->toImplement(Throwable::class)` ends in `DirectoryNotFoundException` when no module has that folder, so the reference's class-shape rules for exceptions, commands, mailables, notifications and jobs cannot be kept in a project before its first such class, and an `arch()` rule has no example form to prove it on ("a rule about something that does not exist yet is built and proved on examples", `04-guards.md` C1). The starter keeps the rules for folders that exist; the names of the rest are held by `ModuleLayoutGuard` (Name column). Repro: run the reference `ArchClassShapeTest.php` in an app without `app/Modules/*/Exceptions`.
40. **`ArchHttpTest`, `ArchModelsTest`, `ArchContainerTest` and `ArchClassShapeTest` of the reference each hold several guards, some of them tenant, Inertia or TypeScript guards.** A single-tenant API cannot keep the file and cannot delete it: each guard's three parts sit in the one file, so the guard folder rule "a guard test file names its guard" is met by name, not by topic. Ported by one thin test per guard (`DateCastArchitectureTest`, `ModelConventionArchitectureTest`, `ControllerNameArchitectureTest`, `ScheduledOneServerArchitectureTest`, `BootstrapRegistrationArchitectureTest`, `ConfigAccessArchitectureTest`, ...).
41. **`ScheduledOneServerGuard` fails a project with no scheduled task.** Its real-tree case needs at least one `Schedule::command(...)` ("no scheduled task was read"), so a starter with an empty schedule cannot run it. The starter schedules `sanctum:prune-expired` (a real need: tokens accumulate) in `routes/console.php`, with `onOneServer()` and an explicit `withoutOverlapping(60)`, and wired it in `bootstrap/app.php` (`commands:`).
42. **The phase 1 `PestArchCall` type has no `expect()`.** `arch('rule')->expect('App\Http')->...` was "Call to an undefined method" at level 10 for every named `arch()` rule; the reference's `PestArchCall` has `expect()` returning `Expectation<mixed>` and the starter's copy had lost it. Restored. Item 6 of this file already names the missing Pest 5 extensions; this is the same family.

## Phase 2 (lead: coverage tests and the guard over the guards)

43. **The guard over the guard folder does not exist in the reference, and its definition of "a real-tree case" is a choice.** The catalog row "Guard shape" prescribes it ("a guard test without a failing-example data set, a passing-example data set or a real-tree case"), but a test cannot tell a passing example from the real-tree case by shape alone: both assert `toBe([])`, and the reference tests build the guard with `dirname(__DIR__, 2)` even for an inline example. `GuardShapeGuard` and `PestExampleReader` read it as: the real-tree case is an `it` with no dataset that builds a root from `dirname(__DIR__, n)`, calls a method named `violations` or `findings` and asserts an empty result; a failing example asserts a non-empty result (a message matcher, `toHaveCount`, `toBeFalse`, an exact non-empty `toBe`); a passing example asserts an empty one and is not the real-tree case. Three of the ported tests needed a split to meet it (a dataset that mixed a boolean for pass and fail, and two tests that held their passing example inside the real-tree case). Repro: `vendor/bin/pest tests/Unit/GuardShapeArchitectureTest.php`.
44. **The reference's coverage tests are written for another application.** `RoutePermissionCoverageTest` and `RouteRateLimitCoverageTest` carry constants for the reference's middleware (an area gate, `web_landlord`, a `rate_limiting.actions` config key), a package namespace list and a dedicated-limiter table, which are exception lists in disguise. The starter's versions read the application's own routes (a controller or closure file under `app` or `routes`), take the public area as an argument, and ask the router for the limiter by name. The kit's "Object-level access" row has no worked example in the reference for an API: `ObjectLevelAccessTest` here is one test over every route with a record id and a map from model to a factory of a foreign record.
45. **`new Route($methods, $uri, SomeController::class)` is not a controller route.** The catalog's route-coverage idea needs synthetic routes for its failing examples, but only `Router::addRoute` turns an invokable class name into `Class@__invoke`; a route built by hand has no controller class, so `signatureParameters()` reflects a method called `null`. Repro: `new Illuminate\Routing\Route(['GET'], 'a/{note}', ShowController::class)` then `->signatureParameters()`. The starter builds them with `'uses' => Class::class . '@__invoke'`.
46. **The guard over the guards fails the CI detector's example class.** `CiExamples` (reference, `tests/Support/Architecture/`) holds the paths of the pipeline files as string literals, which the kit's own rule for the guard folder forbids; the reference README lists it among the files with literal paths. Repro: `vendor/bin/pest tests/Unit/GuardShapeArchitectureTest.php` with the phase 3 files present.

## Phase 3 (pipeline, docs, template script)

Numbered P3-n so they cannot collide with the other phases; renumber when merging.

P3-1. **The reference `GithubWorkflowGuard` never sees `if: false`.** It tests `trim((string) $job['if']) === 'false'`, but the YAML parser returns the boolean `false`, and `(string) false` is `''`. A job or step that is switched off with `if: false` passes. Repro: `Yaml::parse("jobs:\n  a:\n    if: false\n")` then `var_dump(trim((string) $parsed['jobs']['a']['if']) === 'false');` prints `false`. The starter's `GithubJobGuard` compares with `=== false` as well and has a failing example for the job form.
P3-2. **The kit's `tools/doctor.sh` is on the kit's `main` only after its commit is pushed.** The kit at the pinned commit `cfb4405` (the remote head) has no `tools/doctor.sh`; the local kit has it from `cb83cb1`. Any workflow that reads the doctor from a checkout of the kit's default branch fails until then. Repro: `gh api repos/NiekNijland/zero-debt-kit-laravel/contents/tools/doctor.sh` answers 404.
P3-3. **The doctor reports the starter's `ci-ratchets.sh` as `body-differs`, and `--apply` would break its self-test.** The starter added two self-test cases (finding 15: `queue-bus-fake-all`, `unused-ignore`), which sit in the body. `bash tools/doctor.sh --project <starter>` exits 1 with `ci-ratchets.sh body-differs` and `--upgrade-plan --apply` writes the kit's body without those cases, after which `bash scripts/ci-ratchets.sh --self-test` prints "no fixture for". A sync that applies the doctor therefore needs the kit to carry fixtures for every row it names, or to treat the case table as project-owned like the ratchet table.
P3-4. **The GitHub skeleton assumes an image the kit does not provide.** Point 7 of the contract wants every job in an image pinned by digest "with bash, git, curl and tar and the project's toolchain". No official PHP image has PHP, Composer, git, pcov and pdo_pgsql: `serversideup/php:8.4-cli` has Composer and pdo_pgsql, no git and no pcov, and runs as `www-data`. A project must build and publish its own image before it can follow the skeleton. The starter uses `shivammathur/setup-php` on a runner pinned as `ubuntu-24.04` and publishes the service port (`5440:5432`, host `127.0.0.1`); the skeleton shows only the container form (`DB_HOST: database`). Repro: `docker run --rm --entrypoint bash serversideup/php:8.4-cli -c 'git --version; php -m | grep pcov'`.
P3-5. **A workflow that runs `bash scripts/checks.sh` becomes a "kit file" of the contract and may have only the three triggers.** The reader classifies a workflow by its run lines, so a nightly canary or a sync workflow that calls the checks script must carry `pull_request`, `push` and `schedule`, with no manual trigger. The starter's canary runs the ratchet script, the dashboard and the doctor directly instead. The kit does not say that a second workflow must avoid the checks script.
P3-6. **Renaming the package invalidates `composer.lock`.** The content hash covers `name`, so `composer validate --strict` fails after the first edit of `composer.json`. `composer update --lock` repairs it; the kit's template instructions say nothing about the rename. The starter's init script runs it.
P3-7. **`rector-laravel` rewrites `$_SERVER['PATH']` in a unit test into `Request::server('PATH')`,** which throws "A facade root has not been set" in a test that boots no application. Same family as finding 4 (a rule that miscompiles with no way to skip it). Repro: `$_SERVER['PATH']` in a file of `tests/Unit`, `vendor/bin/rector process`, run the test.
P3-8. **The row `loose-comparisons` counts `==` inside strings.** A test fixture that holds a GitHub expression (`github.event_name == 'push'`) or a YAML example counts as a loose comparison, so the contract test's examples had to build the operator at run time. The row cannot tell code from text; the kit offers no exclusion short of a path.
P3-9. **`DocumentedPathGuard` flags a guide that names a file of the kit.** `tools/doctor.sh` is a file of the kit, not of the project; the guard fails it ("no file ends in"). A guide that names the kit's tools writes the bare file name.
P3-10. **Point 15 (analyser paths name every source folder) fails the starter on `lang`.** `SOURCE_PATHS` of the ratchet script holds `lang` (finding 20), `phpstan.neon` does not, and the new `AnalyserPathsGuard` reports it. Adding `lang` to the analyser paths is green (`No errors`).
P3-11. **`doctor.sh --apply` drops the project's extra task lines and the project's fixes, and leaves `PARTS` pointing at tasks that are gone.** Against the starter it removed `"Manifest::..."`, `"Manifest floor::..."` and `"Unused packages::..."` from the `TASKS` array of `checks.sh` (the tasks are a project's to add: `04-guards.md` C4 says so), while the config block keeps `PARTS` naming them, so `checks.sh` stops with "names a task that is no task of this file". It also replaced `mutation.sh` with the kit's body, which lacks the `--processes=4` of finding 17. The doctor's own text says task commands are kept; it keeps the commands of tasks the kit has and drops the others. Repro: copy the starter, `bash tools/doctor.sh --project <copy> --upgrade-plan --apply`, then `git diff scripts/checks.sh`.
P3-12. **`ci-ratchets.sh --head` counts the committed tree, not the working tree.** A new file that is not committed is invisible to every row, so a counter looks 0 while the file breaks it (the starter's contract test fixtures held 25 `==` inside strings, row `loose-comparisons`, and `--head` printed 0 until the files were committed in a scratch copy). The script says "head"; the usage does not say "committed". Repro: add an untracked PHP file with `if ($a == $b) {}` and run `bash scripts/ci-ratchets.sh --head`.
